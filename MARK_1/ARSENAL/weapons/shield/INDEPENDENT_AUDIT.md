## Summary
SHIELD is a structured input-boundary hardening layer (not a weapon) built around four kappa=1 deterministic rails (provenance labeling, verifier taint-rail, tool-cape HMAC allowlist, cert anti-replay) plus a kappa=0 abstain-or-escalate rail. The selftest suite passes cleanly at exit 0, covers genuine adversarial cases including object.__setattr__ relabeling, Span subclassing spoofs, future-dated certs, and non-syntactic semantic injection, and the demo runs 7/7. The tool genuinely discriminates: it correctly blocks tainted inputs, forged capes and certs, out-of-allowlist tool calls, and self-elevation attempts, while never emitting a false "injection-free" clearance. Three concretely reproducible crashes were found (non-string sig field in verify_cert, non-JSON-serializable objects in issue_cert, mixed-type allowlists in issue_cape) -- these are robustness defects in error-path handling rather than soundness holes in the primary threat model, and none are reachable via the selftested happy paths. A fourth design-level caveat is that the taint-rail API silently treats any non-Span, non-marked-dict value as untainted, requiring all callers to wrap external content in Span objects; this contract is not enforced in the function signature.

## Defects found (4)
1. verify_cert crashes (TypeError) instead of returning REJECT when the cert's 'sig' field is not a string (e.g. None, int, list, dict). Root cause: hmac.compare_digest(_sign(...), cert['sig']) raises TypeError on non-string/bytes input. A malformed cert that passes the 'sig' key presence check but carries a wrong type causes an unhandled exception rather than a clean REJECT. The selftest never exercises a non-string sig value.
2. issue_cert (via _object_hash -> _canonical) crashes with TypeError when the object to certify is a non-JSON-serializable Python type such as a set or a custom object. _object_hash falls through to _canonical (json.dumps) for anything that is not bytes/bytearray; json.dumps raises on set, datetime, etc. The selftest only tests dicts and bytes.
3. issue_cape crashes with TypeError when the allowlist contains mixed comparable types (e.g. [1, 'a']). sorted(set(allowlist)) raises '<' not supported between instances of 'str' and 'int'. The selftest always passes string-only allowlists.
4. The VERIFIER TAINT-RAIL (_is_tainted) only flags two forms of tainted value: (a) Span objects whose internal HMAC token reads ENV, and (b) plain dicts that explicitly carry {'_taint': 'ENV'}. Any other external-origin value -- a raw string, a list, a dict without the marker -- passes the taint check silently. The rail relies entirely on callers being disciplined enough to always wrap external content as Span objects before passing it. There is no defensive type check on frozen_code/system_spec: passing a raw string (even one that arrived from an attacker) returns PASS_TAINT_CHECK. This is a documented design choice but creates a fragile API contract that is not enforced or documented in gate_inputs_ok's signature.
